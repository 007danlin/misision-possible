# О!дин запрос · MISISION POSSIBLE

Актуальные возможности, проверенные сценарии и оставшиеся условия сдачи: [единая поездка — отчёт](docs/whole-trip-verification-2026-10-27.md).

Агент для путешествий по России: свободный запрос → направления → сравнение поездок → пересборка бюджета/дат → учебное оформление. При изменениях сохраняет остальные условия и показывает разницу стоимости и условий отмены.

**Реальных бронирований и списаний нет.** Основной `/plan.html` собирает отель, дорогу туда-обратно и оба трансфера с общей ценой и проверкой состыковок. Полная поездка использует реальные публичные карточки, фото, правила и доступные отзывы Островка. Для дороги сравниваются самолёт, поезд и автомобиль; выбор пересчитывает общий итог и трансферы. Подключены кэш прямых перелётов Aviasales/Travelpayouts (необязательный ключ), кэш поездов Tutu Москва ↔ Сочи, маршруты OSRM, карта OpenStreetMap и прогноз MET Norway. Данные из кэша не гарантируют наличие на даты; проживание и трансферы остаются оценкой. Город отправления уточняется, а геолокация применяется только после подтверждения. Направления полной поездки: Сочи, Казань, Ярославль, Сортавала, Петербург и Владимир; основания расчёта дороги различаются для разных городов отправления.

## Быстрый старт

Нужны Git, Docker с Compose и доступ в интернет для первой сборки/загрузки модели. Модель работает локально внутри контейнера; API-ключ не нужен.

```sh
git clone https://github.com/ostrovok-hackathon-2026/misision-possible.git
cd misision-possible
docker compose up --build
# во время подготовки открыть http://localhost:8080 — там виден прогресс
```

Создавать `.env`, устанавливать Ollama/Python/Go и скачивать модель вручную не нужно. Docker автоматически выбирает архитектуру компьютера: ARM64 на Apple Silicon, AMD64 на x86-64. Не задавайте `DOCKER_DEFAULT_PLATFORM` для эмуляции другой архитектуры: это замедляет модель. `.env.example` нужен только для необязательных настроек.

При первом запуске контейнер `model` автоматически скачивает 5,68 ГБ весов Qwen3.5-9B Q4_K_M и проверяет SHA-256. Веса сохраняются в Docker volume; повторно не скачиваются. После сборки интерфейс открывается сразу: показывает процент и скорость загрузки, проверку весов, загрузку в память и прогрев. Когда модель готова, страница автоматически открывает приложение. Прогресс также виден в выводе Compose. При обрыве сети загрузка повторяется с сохранённого места, если источник поддерживает докачку. Первичная установка зависит от скорости сети; обещать запуск до 10 минут без замера на целевой машине нельзя.

Рекомендация для проверки: 16 ГБ RAM, выделенных Docker, 4–8 CPU и 15 ГБ свободного диска. Это ориентир, а не измеренный минимальный порог. **Полный UI-сценарий Docker/CPU на текущем Mac не прошёл: таймауты 180 и 300 с. Эта конфигурация пока не готова для сдачи без проверки на целевом железе.** Для текущего Mac используйте нативный Metal-запуск ниже; замеры см. в отчёте. Если Docker доступно только 8 ГБ, запас памяти невелик.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_PROVIDER` | `llama_cpp` | Локальный inference; также поддержаны `ollama`, `dashscope`, `openai_compatible` |
| `LLM_BASE_URL` | `http://model:8082/v1` | Адрес модели из сети контейнеров |
| `LLM_MODEL` | `qwen3.5-9b` | Имя модели в inference server |
| `LLM_API_KEY` | пусто | Локальной модели не нужен; секрет внешнего провайдера нельзя коммитить |
| `AGENT_TURN_TIMEOUT_SECONDS` | `300` | Общий предел хода в Docker; допустимо 1–300 с; это лимит, а не нормальное время ожидания |

Нативный launcher для Mac использует Metal и по умолчанию лимит 180 с, чтобы запрос не обрывался при высокой нагрузке. Лимит можно изменить через `AGENT_TURN_TIMEOUT_SECONDS` после перезапуска сервисов. Облачная модель не является зависимостью основного запуска и не проверена без доступа к провайдеру.

## Готовность и диагностика

```sh
docker compose ps
docker compose logs model
docker compose logs agent app
docker compose exec agent python -m travel_agent.model_check
```

Healthcheck агента проверяет gRPC, healthcheck модели — готовность загрузки. `model_check` отдельно делает настоящий запрос к модели и проверяет извлечение города; успех `/health` приложения не заменяет полный сценарий.

- `/` — главная Островка с обычным поиском и входом в ИИ.
- `/plan.html` — умный подбор: единая поездка или отдельное размещение в зависимости от запроса; подробности, отзывы и оформление внутри страницы.
- `/plan.html?mode=demo` — прежний сценарий полной поездки на отдельном каталоге.
- `/health` — JSON `{"status":"ok"}`.
- `/api/sessions/` — создание поездки; `/api/sessions/{id}` — состояние.
- `/api/sessions/{id}/turns` — сообщение; `/api/sessions/{id}/actions` — выбор, принятие изменения, учебное оформление.

Регистрация для локального демо не нужна. Владение сессией хранится в HttpOnly/SameSite cookie; данные сохраняются в volume `trips`. Порт опубликован только на loopback компьютера. Это демо для одного экземпляра Core, а не production-сервис.

```sh
docker compose down
# Не добавляйте -v, если нужно сохранить поездки и скачанную модель.
```

Каталоги встроены в пакет агента. Основной интерфейс использует публичные страницы Островка с кэшем; явно включаемый `JOURNEY_DATA_SOURCE=synthetic` использует [journey_catalogue.json](agent/travel_agent/journey_catalogue.json), прежний режим — [catalogue.json](agent/travel_agent/catalogue.json). Новые маршруты требуют полного набора тарифов, расписаний, трансферов и условий, а не только названия города. [Правила прежнего учебного расчёта](docs/catalogue.md).

## Проверочный сценарий

1. «Из Москвы в Сочи, 10–15 ноября 2026, двое взрослых. 120 тысяч рублей на дорогу, отель и оба трансфера. Без ночных рейсов, нужен бассейн».
2. Если запрошен резерв на личные расходы: «Резерв на личные расходы 0 рублей».
3. Открыть первый настоящий отель: общая оценка зависит от текущей справочной цены. Проверить отзывы по теме, дорогу и время трансферов; перейти к оформлению.
4. Изменить выезд на 17 ноября: сравнить прежнюю и новую общую стоимость, вернуть прежний план или принять изменение.
5. Подтвердить учебное оформление; обновить страницу и скачать PDF с сохранённой общей ценой и маршрутом. Автоматическая проверка: `node scripts/ui-public-journey.cjs`.

## Архитектура и ограничения

LLM извлекает изменённые условия с цитатами пользователя. Инструменты считают цены и проверяют ограничения. Core хранит авторитетное состояние, ревизии и идемпотентность; только явное действие пользователя создаёт учебный заказ. Модель не записывает стоимость и не разрешает покупку.

- [Контракты и архитектура](docs/agent.md), [JSON-схемы](agent/schemas/).
- [Историческая проверка 24 октября](docs/agent-evaluation.md), [актуальные результаты](docs/submission-status.md).
- [Нативный запуск на Mac с Metal](docs/local-setup.md): `python3 scripts/local.py start`, адрес `http://127.0.0.1:18080`.
- Исходный сервисный стек команды сохранён в `infra/docker-compose.*.yml`; основной локальный сценарий использует Core, agent и model без необязательных Auth/Chat/Notif/мониторинга.

Нет реальных поставщиков, оплаты, полного покрытия России или подтверждённой доступности для детей/питомцев. Для таких условий агент уточняет запрос или честно сообщает об отсутствии предложения. Новые пользовательские формулировки могут выявлять ошибки модели; открытые тесты не доказывают универсальную надёжность.

### Транспорт, карты и погода

`TRAVELPAYOUTS_TOKEN` — необязательный серверный токен Data API; храните его в `.env` или окружении, не в Git. Нативный launcher также читает `.runtime/secrets/travelpayouts.env`. В контейнер передаётся только агенту. `MAP_TILE_URL` меняет поставщика подложки; пустое значение использует стандартные OSM tiles. `PUBLIC_DATA_USER_AGENT` задаёт идентификатор приложения для MET Norway. Ключи не включаются в ссылки или данные браузера. Подробнее: [реестр источников](docs/public-data-sources.md).

## Передача секретов организаторам

Основной LLM-провайдер — локальный llama.cpp, модель Qwen3.5-9B Q4_K_M; ключ LLM не требуется. `.env.example` содержит имена переменных с пустыми значениями: Docker Compose подставляет значения по умолчанию. Необязательный `TRAVELPAYOUTS_TOKEN` берётся из кабинета Travelpayouts Data API. При использовании внешнего LLM создайте отдельный ключ для жюри и укажите провайдера и модель в настройках.

В корне репозитория находится бинарный `secrets.env.age`, зашифрованный публичным ключом организаторов. Открытый `.env` остаётся локальным и исключён из Git. После любого изменения `.env` обновите зашифрованный файл:

```sh
age -r age1932fu7f70rwyfhaxflyfszz4gf6avxwc95wc0yjwm6zns9tspycqpgdnc0 -o secrets.env.age .env
git ls-files .env  # вывод должен быть пустым
git add secrets.env.age .env.example .gitignore README.md
```

Зашифрованный файл должен попасть в коммит и ветку сдачи. Расшифровать его можно только закрытым ключом организаторов; открытые ключи API не отправляйте в чат или документацию.
