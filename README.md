# 🏖️ О!дин запрос

**Трек:** «О!дин запрос» · **Команда:** MISISION POSSIBLE · **Помощник в интерфейсе:** О!План.

AI-агент для путешествий по России: понимает свободный запрос, уточняет пожелания, сравнивает варианты и собирает отель, дорогу и трансферы в единый план. При изменении бюджета или дат сохраняет остальные условия и показывает разницу стоимости.

**Бронирование и оплата имитируются.** Цены справочные или расчётные; наличие на выбранные даты не гарантируется.

**Видео-скринкаст:** команда добавит публичную ссылку на запись актуального интерфейса перед сдачей. Ссылка должна открываться в режиме инкогнито без авторизации.

## Быстрый старт

Нужны Git, Docker с Compose и доступ в интернет для первой сборки/загрузки модели. Модель работает локально внутри контейнера; API-ключ не нужен.

```sh
git clone https://github.com/ostrovok-hackathon-2026/misision-possible.git
cd misision-possible
docker compose up --build
# во время подготовки открыть http://localhost:8080 — там виден прогресс
```

Создавать `.env`, устанавливать Ollama/Python/Go и скачивать модель вручную не нужно. Docker автоматически выбирает архитектуру компьютера: ARM64 на Apple Silicon, AMD64 на x86-64. Не задавайте `DOCKER_DEFAULT_PLATFORM` для эмуляции другой архитектуры: это замедляет модель. `.env.example` нужен только для необязательных настроек.

### Что происходит после запуска и сколько ждать

**Первый запуск не мгновенный.** На проверенном MacBook Air M4 подготовка заняла около 4 минут. На медленном компьютере, при слабом интернете или под эмуляцией она может занять **10–15 минут или больше**. Это ориентир для ожидания, а не обещание готовности за фиксированное время. Организаторы рекомендуют установку примерно до 10 минут; более долгий запуск остаётся ограничением, а не выполнением этого ориентира.

1. **Сборка контейнеров.** Прогресс виден в терминале с `docker compose up --build`. Пока веб-сервер не собран и не запущен, `localhost:8080` может быть недоступен.
2. **Скачивание модели.** Откройте `http://localhost:8080`: страница подготовки показывает процент, полученный и полный объём в ГБ и скорость. Автоматически скачиваются 2,50 ГБ весов Qwen3-4B-Instruct-2507 Q4_K_M. При обрыве сети загрузка повторяется с сохранённого места, если источник поддерживает докачку.
3. **Проверка и загрузка в память.** Проверяется SHA-256, затем запускается модель. **100% скачивания ещё не означает готовность приложения.**
4. **Прогрев — подготовка первого ответа.** На странице отображается текущий этап. Процент прогрева не рассчитывается: этот этап может несколько минут выглядеть без изменений. Не перезапускайте контейнеры только из-за того, что процент скачивания уже достиг 100%.
5. **Готовность.** После прогрева страница автоматически откроет приложение. Можно оставить вкладку открытой; терминал с Compose также оставьте работающим.

Веса сохраняются в Docker volume и при повторном запуске не скачиваются. **После перезапуска процесса модели прогрев всё равно нужен**, поэтому повторный запуск тоже занимает время. На проверенном M4 холодная сборка с новым builder и пустыми volumes заняла 3 мин 56 с до всех healthy; экран подготовки открылся за 45 с. Повторный запуск с сохранёнными весами — 1 мин 33 с. Эти замеры не гарантируют ту же скорость на другом компьютере.

### Если прогрев не укладывается в лимит

По умолчанию отдельный прогрев ограничен **300 секундами (5 минутами)**; время скачивания в этот лимит не входит. Если в `docker compose logs agent` появляется `model_timeout`, ожидание само по себе не увеличит лимит. Для медленной машины или эмуляции добавьте в корневой `.env` (создайте файл, если его нет; существующие настройки сохраните):

```dotenv
MODEL_WARMUP_TIMEOUT_SECONDS=900
AGENT_TURN_TIMEOUT_SECONDS=300
```

Повторите `docker compose up --build`. Это разрешит **до 15 минут на сам прогрев** и до 5 минут на отдельный пользовательский запрос; сборка и скачивание могут потребовать дополнительного времени. Эти значения — пределы ожидания, а не обязательная задержка: как только модель готова, приложение открывается. Основной запуск без `.env` продолжает использовать стандартные лимиты.

Если после увеличения лимита подготовка снова завершается ошибкой, проверьте свободную RAM, доступ к интернету и `docker compose logs agent model`; бесконечно ждать страницу подготовки не нужно. Подробности успешного прогона с увеличенными лимитами приведены в [проверке AMD64](docs/validation/amd64-2026-10-28/README.md).

Проверенный режим: **4 общих ядра CPU, без GPU, 5,75 GiB лимитов RAM на весь стек**, без swap контейнеров. Выделите Docker не менее 6 GiB RAM и оставьте запас памяти для ОС; для сборки и кэшей желательно 15 ГБ свободного диска. Самой модели разрешено 5 GiB, агенту 512 MiB, приложению 256 MiB. Это измеренный режим на MacBook Air M4, а не гарантия такой же скорости на старом x86 или компьютере с 4 ГБ общей RAM.

**Docker/CPU: 95/95 фраз, медиана 3,62 с, p95 8,52 с; полный браузерный сценарий до reload и PDF прошёл.** Начальный сложный запрос в UI — 16,16 с после прогрева. Прямые команды интерфейса используют проверяемые операции без лишнего вызова модели. [Профилирование, сравнение моделей, холодный запуск и ограничения](docs/validation/docker-cpu-2026-10-27/README.md). [Независимая проверка чистой сборки](docs/compose-bootstrap-check-2026-10-28.md).

**Intel/AMD (Linux AMD64):** образы собраны, запуск и браузерный сценарий до покупки/PDF проверены через эмуляцию на Apple Silicon. Штатный прогрев 300 с в эмуляции завершился таймаутом; успешный прогон использовал лимиты 900 с для прогрева и 300 с для запроса. Это проверка совместимости, не замер на физическом Intel. [Результаты и воспроизведение](docs/validation/amd64-2026-10-28/README.md).

## Зависимости и переменные окружения

Основной Compose поднимает три сервиса: `app` (Go Core и веб-интерфейс, порт 8080), `agent` (Python/gRPC) и `model` (llama.cpp с Qwen). PostgreSQL, Redis, SMTP и отдельная регистрация для этого режима не нужны. Внешние источники и границы данных описаны [отдельно](docs/public-data-sources.md).

Настройки необязательны. Чтобы изменить их, скопируйте `.env.example` в `.env` в корне репозитория, заполните нужные значения и повторите `docker compose up --build`. В macOS/Linux: `cp .env.example .env`; в PowerShell: `Copy-Item .env.example .env`. Не перезаписывайте уже заполненный `.env`. Пустые значения используют defaults из Compose.

Ниже перечислены все пользовательские переменные корневого Compose. Внутренние адреса, порты и пути сервисов заданы в `docker-compose.yml` и не требуют настройки.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_PROVIDER` | `llama_cpp` | Локальный inference; также поддержаны `ollama`, `dashscope`, `openai_compatible` |
| `LLM_BASE_URL` | `http://model:8082/v1` | Адрес модели из сети контейнеров |
| `LLM_MODEL` | `qwen3-4b-instruct` | Имя модели в inference server |
| `LLM_API_KEY` | пусто | Локальной модели не нужен; секрет внешнего провайдера нельзя коммитить |
| `AGENT_TURN_TIMEOUT_SECONDS` | `90` | Общий предел хода в Docker; допустимо 1–300 с; это лимит, а не нормальное время ожидания |
| `MODEL_WARMUP_TIMEOUT_SECONDS` | `300` | Отдельный предел первого прогрева при запуске; не меняет лимит пользовательского запроса |
| `MODEL_LOCK` | `docs/docker-runtime.json` | Закреплённые версия, размер и SHA-256 Docker-модели |
| `MODEL_THREADS` | `4` | Потоки CPU; на машине с двумя ядрами задайте 2, её скорость отдельно не принята |
| `MODEL_CONTEXT` | `4096` | Размер контекста каждого из двух слотов модели |
| `MODEL_CHECKPOINTS` | `2` | Число контрольных точек контекста inference |
| `MODEL_CACHE_RAM` | `0` | Дополнительный кэш inference, MiB; два прогретых контекста закреплены в отдельных слотах |
| `JOURNEY_DATA_SOURCE` | `public` | Публичные данные с кэшем; `synthetic` — учебный каталог |
| `TRAVELPAYOUTS_TOKEN` | пусто | Необязательный серверный токен кэша авиаперелётов Travelpayouts Data API |
| `MAP_TILE_URL` | пусто | При пустом значении приложение использует `https://tile.openstreetmap.org/{z}/{x}/{y}.png` |
| `PUBLIC_DATA_USER_AGENT` | `OPlan-Hackathon/1.0 https://github.com/ostrovok-hackathon-2026/misision-possible` | Идентификатор клиента публичных источников, в том числе MET Norway |

`AGENT_TOOLS_MODE=demo` зафиксирован внутри Compose: учебное оформление не выполняет настоящую покупку. Это не переключатель источника данных; для источника используется `JOURNEY_DATA_SOURCE`.

Нативный launcher для Mac использует Metal и по умолчанию лимит 180 с, чтобы запрос не обрывался при высокой нагрузке. Лимит можно изменить через `AGENT_TURN_TIMEOUT_SECONDS` после перезапуска сервисов. Облачная модель не является зависимостью основного запуска и не проверена без доступа к провайдеру.

## Готовность и диагностика

```sh
docker compose ps
docker compose logs model
docker compose logs agent app
docker compose exec agent python -m travel_agent.model_check
```

Healthcheck приложения проверяет `/ready`, агента — gRPC, модели — готовность загрузки. `model_check` отдельно делает настоящий запрос к модели и проверяет извлечение города; успех `/health` приложения не заменяет полный сценарий.

- `/` — главная Островка с обычным поиском и входом в ИИ.
- `/plan.html` — умный подбор: единая поездка или отдельное размещение в зависимости от запроса; подробности, отзывы и оформление внутри страницы.
- `/plan.html?mode=demo` — прежний сценарий полной поездки на отдельном каталоге.
- `/health` — работоспособность процесса, HTTP 200 и JSON `{"status":"ok"}`.
- `/ready` — готовность модели и агента: HTTP 200 после подготовки, HTTP 503 во время ожидания.
- `/api/runtime/status` — текущий этап подготовки и прогресс загрузки модели.
- `/api/sessions/` — создание поездки; `/api/sessions/{id}` — состояние.
- `/api/sessions/{id}/turns` — сообщение; `/api/sessions/{id}/actions` — выбор, принятие изменения, учебное оформление.

Регистрация для локального демо не нужна. Владение сессией хранится в HttpOnly/SameSite cookie; данные сохраняются в volume `trips`. Порт опубликован только на loopback компьютера. Это демо для одного экземпляра Core, а не production-сервис.

```sh
docker compose down
# Не добавляйте -v, если нужно сохранить поездки и скачанную модель.
```

## Демо-данные и хранение

**Ручные миграции и сидирование не требуются.** Каталоги встроены в пакет агента. Основной интерфейс использует публичные страницы Островка с кэшем; явно включаемый `JOURNEY_DATA_SOURCE=synthetic` использует [journey_catalogue.json](agent/travel_agent/journey_catalogue.json), прежний режим — [catalogue.json](agent/travel_agent/catalogue.json). Новые маршруты требуют полного набора тарифов, расписаний, трансферов и условий, а не только названия города. [Правила прежнего учебного расчёта](docs/catalogue.md).

Поездки сохраняются автоматически в volume `trips`, кэш публичных данных — в `hotel-content`, веса модели — в `models`, состояние подготовки — в `startup`. Для режима `public` нужен интернет к источникам; недоступность источников может ограничить выдачу. Для учебного каталога задайте `JOURNEY_DATA_SOURCE=synthetic` в `.env` и повторите запуск. Даже в этом режиме первая установка требует интернета для образов и весов.

## Проверочный сценарий

1. «Из Москвы в Сочи, 10–15 ноября 2026, двое взрослых. 120 тысяч рублей на дорогу, отель и оба трансфера. Без ночных рейсов, нужен бассейн».
2. Если запрошен резерв на личные расходы: «Резерв на личные расходы 0 рублей».
3. Открыть первый настоящий отель: общая оценка зависит от текущей справочной цены. Проверить отзывы по теме, дорогу и время трансферов; перейти к оформлению.
4. Изменить выезд на 17 ноября: сравнить прежнюю и новую общую стоимость, вернуть прежний план или принять изменение.
5. Подтвердить учебное оформление; обновить страницу и скачать PDF с сохранённой общей ценой и маршрутом. Сценарий для разработчиков: `scripts/ui-public-journey.cjs` (Node.js и браузерные зависимости нужны только для автоматизации проверки, не для запуска приложения).

## Архитектура и ограничения

LLM извлекает изменённые условия с цитатами пользователя. Инструменты считают цены и проверяют ограничения. Core хранит авторитетное состояние, ревизии и идемпотентность; только явное действие пользователя создаёт учебный заказ. Модель не записывает стоимость и не разрешает покупку.

- [Контракты и архитектура](docs/agent.md), [JSON-схемы](agent/schemas/).
- [Историческая проверка 24 октября](docs/agent-evaluation.md), [актуальные результаты](docs/submission-status.md).
- [Нативный запуск на Mac с Metal](docs/local-setup.md): `python3 scripts/local.py start`, адрес `http://127.0.0.1:18080`.
- Исходный сервисный стек команды сохранён в `infra/docker-compose.*.yml`; основной локальный сценарий использует Core, agent и model без необязательных Auth/Chat/Notif/мониторинга.

Нет реальных поставщиков, оплаты, полного покрытия России или подтверждённой доступности для детей/питомцев. Для таких условий агент уточняет запрос или честно сообщает об отсутствии предложения. Новые пользовательские формулировки могут выявлять ошибки модели; открытые тесты не доказывают универсальную надёжность.

### Транспорт, карты и погода

`TRAVELPAYOUTS_TOKEN` — необязательный серверный токен Data API; храните его в `.env` или окружении, не в Git. Нативный launcher также читает `.runtime/secrets/travelpayouts.env`. В контейнер передаётся только агенту. `MAP_TILE_URL` меняет поставщика подложки; пустое значение использует стандартные OSM tiles. `PUBLIC_DATA_USER_AGENT` задаёт идентификатор приложения для MET Norway. Ключи не включаются в ссылки или данные браузера. Подробнее: [реестр источников](docs/public-data-sources.md).

## Передача секретов организаторам

Основной Docker LLM-провайдер — локальный llama.cpp, модель Qwen3-4B-Instruct-2507 Q4_K_M; ключ LLM не требуется. `.env.example` содержит имена переменных с пустыми значениями: Docker Compose подставляет значения по умолчанию. Необязательный `TRAVELPAYOUTS_TOKEN` берётся из кабинета Travelpayouts Data API. При использовании внешнего LLM создайте отдельный ключ для жюри и укажите провайдера и модель в настройках.

В корне репозитория находится бинарный `secrets.env.age`, зашифрованный публичным ключом организаторов. Размещение именно в корне, вместе с `.env.example`, — прямое требование [инструкции организаторов](https://docs.ostrovok.tech/s/b9e6ec5e-5ad6-4091-9c85-a48eee9b21cc/doc/shifrovanie-sekretov-klyuchej-6Qhc4gJOPZ). Конфигурация инфраструктуры хранится в `infra/`; файл передачи секретов остаётся в корне.

По записи о передаче секретов в зашифрованный `.env` включён `TRAVELPAYOUTS_TOKEN`; актуальность токена проверяется при обращении к провайдеру. Он нужен для кэша прямых авиаперелётов и передаётся только серверному агенту. Локальной Qwen, публичным карточкам отелей, OSRM, OpenStreetMap, MET Norway и Open-Meteo отдельные ключи не нужны. Основной запуск через корневой Compose не зависит от SMTP, PostgreSQL или JWT: эти настройки относятся к отдельному необязательному стеку в `infra/`.

Организаторам для запуска с переданным токеном нужно расшифровать файл своим закрытым ключом в корне клона и запустить Compose:

```sh
age --decrypt -i /path/to/organizer-private-key -o .env secrets.env.age
docker compose up --build
```

Compose автоматически читает корневой `.env`. В нём используется адрес модели внутри Docker (`http://model:8082/v1`), поэтому локальные службы на компьютере разработчика не нужны. Открытый `.env` остаётся локальным и исключён из Git. После любого изменения `.env` обновите зашифрованный файл:

```sh
age -r age1932fu7f70rwyfhaxflyfszz4gf6avxwc95wc0yjwm6zns9tspycqpgdnc0 -o secrets.env.age .env
git ls-files .env  # вывод должен быть пустым
git add secrets.env.age .env.example .gitignore README.md
```

Зашифрованный файл должен попасть в коммит и ветку сдачи. Расшифровать его можно только закрытым ключом организаторов; открытые ключи API не отправляйте в чат или документацию.
