# Учебный каталог и расширение по России

Данные находятся в `agent/travel_agent/catalogue.json`, алгоритм — в `demo_tools.py`.
Версия: `synthetic-russia-v2`. Все тарифы, наличие, условия и расписания учебные.

## Покрытие

- Отправление: Москва. Направления: Сочи, Казань, Владимир, Ярославль.
- Два взрослых, без детей. Размещение с питомцами не подтверждено.
- Заезд не раньше 1 ноября 2026, выезд не позже 31 декабря 2026.
- От 1 до 14 ночей. Количество календарных дней = ночи + 1.
- Три комбинации A/B/C; у B нет бесплатной отмены, у A/C она условно есть.

Это покрытие демонстрационных данных, не ограничение архитектуры городами или этими датами.
За пределами каталога агент сообщает об отсутствии данных и не подменяет условия.

## Расчёт

В `costs` для каждого варианта перечислены рублёвые стоимости:
`[дорога туда-обратно, проживание за 5 ночей, оба трансфера, сборы]` для двух взрослых.

1. Стоимость проживания = базовое проживание × ночи / 5, округление вниз до рубля.
2. К базовой дороге добавляется `((дата заезда − 10.11.2026) mod 7) × 1000` рублей.
3. Трансферы и сборы не зависят от длительности.
4. Итог — сумма компонентов; в API деньги передаются целыми копейками.

Формула иллюстрирует сменные тарифы. Она не описывает рынок, сезонность или реальное наличие.
Пример: Сочи A на 10–15 ноября = 109 000 ₽; перенос на 12–17 ноября = 111 000 ₽.
Ярославль A на 3–7 ноября = 22 800 ₽ (7 000 + 12 800 + 2 000 + 1 000).

Бюджет `booking` проверяется по всей сумме бронируемых услуг. Для `hotel` проверяется
проживание, но пользователю показывается и полная сумма услуг. Для `whole_trip` из бюджета
сначала вычитается согласованный резерв других расходов; неизвестный резерв требует уточнения.

## Как добавить направление

Добавить запись в `destinations` с уникальным ASCII `id`, названием, описанием и тремя
наборами тарифов. Пересобрать агент. Код извлечения запроса, поиска, выбора направления и
оформления менять не требуется. Ярославль добавлен именно этим способом и проверяется
`tests/test_catalogue.py`. UI сейчас перечисляет покрытие явно: при добавлении города
также обновить поясняющий текст и README, чтобы они соответствовали данным.

Реальная интеграция заменяет реализацию `ToolRegistry`; цены, условия и источники должны
приходить от поставщика. Одна запись JSON не является интеграцией с реальным бронированием.

## Совместимость с сохранёнными поездками

Старые ID пяти ночей (`sochi:2026-11-10:A`) сохранены. Для другой длительности ID включает
дату выезда (`yaroslavl:2026-11-03:2026-11-07:A`). Перед оформлением цена, даты и условия
восстанавливаются по ID и проверяются заново. Переданная клиентом стоимость не авторитетна.
