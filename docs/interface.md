# Островок + О!План: прототип умного подбора

> Обновление: основной интерфейс теперь собирает также полную поездку. Актуальные возможности, источники и границы описаны в [реализации P0](journey-implementation.md). Разделы ниже содержат историю предыдущих изменений.


## Главная из вебархива

`/` использует исходные HTML, CSS, шрифты и изображения предоставленного
Ostrovok.webarchive. Сохранены все десять секций главной, исходная шапка,
карусели и подвал. Добавлена плашка «А можно просто рассказать о планах».
Архив содержит главную; страницы по внешним ссылкам открываются на Островке.
Сохранённые акции и суммы главной — снимок на дату архива.

Оригинальные сторонние скрипты, аналитика, iframe и авторизация не запускаются.
Поведение элементов реализовано локально в `archive-home.js`:

- даты, гости, город и фильтр квартир передаются в обычный поиск Островка;
- карусели прокручиваются, логотип возвращает на локальную главную;
- демовход сохраняет только имя в браузере; это не аккаунт Островка;
- подписка демонстрирует подтверждение без отправки адреса или писем;
- остальные сервисы открываются по исходным ссылкам или явно обозначенным
  информационным диалогам прототипа;
- у архивного canvas QR нет сохранённых пикселей: его заменяет рабочая ссылка
  на приложение. Изображения, которых нет среди ресурсов архива, загружаются
  напрямую по исходным CDN-ссылкам.

## Умный подбор

`/plan.html`: Qwen извлекает изменения условий из сообщения. Перед каждым
ходом модель получает актуальные условия, последние сообщения, предыдущий
ответ помощника и названия показанных вариантов. Новые значения требуют
дословных цитат из запроса. Одно изменение не сбрасывает остальные поля.

Пожелания: бассейн, парковка, спа, фитнес, завтрак, расстояние до центра/пляжа,
минимальные рейтинг и звёзды, питомцы, отмена, даты/число ночей, гости, бюджет
на весь срок или за ночь. Снятие требования — отдельная операция
`remove_hotel_preferences`, например «бассейн больше не обязателен».

Инструмент читает весь список отелей текущей публичной страницы (в живой
проверке — 20). Это не полный инвентарь Островка. Затем отдельный селектор:

1. Фильтрует обязательные признаки по данным каталога. Неизвестный признак
   не считается подтверждённым.
2. Рассчитывает демотариф и проверяет бюджет.
3. Ранжирует подходящие варианты по оценке гостей, числу отзывов и расстояниям,
   если они запрошены. «Подешевле» меняет сортировку по стоимости.
4. Возвращает до трёх вариантов, причины выбора, число рассмотренных и
   подходящих отелей. При отсутствии совпадений предлагает изменить условия,
   но не ослабляет их самостоятельно.

Неизвестные пожелания вроде тишины сохраняются и выводятся как требующие
уточнения. Вопрос «почему второй?» объясняет второй показанный вариант без
нового поиска. Если не хватает сведений для бюджета, задаётся один вопрос.

## Какие данные демонстрационные

Названия, фото, адреса, удобства, расстояния, оценки и отзывы взяты из
публичного каталога. Партнёрского API тарифов у команды нет.

`hotel_selection.demo_quote` — **явная заглушка тарифного провайдера**:
справочная цена без дат округляется до 100 рублей за номер, число номеров
моделируется по два гостя, завтрак добавляет 650 рублей на гостя за ночь,
возвратный тариф — 12%. Итог умножается на число ночей. Даты определяют
длительность, но реальное наличие и сезонная стоимость не подтверждаются.
На каждой сумме есть метка «Демо», полное объяснение — в подробностях.

При смене числа гостей/ночей бюджет пересчитывается; завтрак и отмена относятся
к демотарифу, а не к подтверждённому предложению Островка. Ошибка источника
не подменяется выдуманным списком. Настоящая цена проверяется по внешней ссылке.

## Интерфейс и состояние

Компактная шапка «Умный подбор», ниже значок земного шара, регион и карандаш.
Карандаш открывает страну и город; изменение сохраняет остальные условия.
Доступны российские направления и несколько проверенных городов Беларуси,
Турции, Франции и Италии. Фразы про «фото для настроения» удалены.

Core хранит сессии, ревизии и идемпотентность. История восстанавливается после
перезагрузки. `/plan.html?mode=demo` сохраняет прежний учебный сценарий полной
поездки с дорогой, изменением плана и учебным оформлением. Сессии разделены.
Локальный лимит Qwen — 180 секунд.

## Окно в поездку и оформление внутри сайта (27.10)

В `/plan.html` кнопка «Выбрать отель» открывает оформление внутри приложения. Core сохраняет `selected_hotel`, затем `hotel_booking` с неизменяемым снимком отеля, тарифа, гостей, дат и номера подтверждения. Запрос `select_hotel` принимает только ID из актуальной подборки. `confirm_hotel_booking` принимает дату заезда, имя гостя и явное подтверждение показа прототипа; сумма берётся только из сохранённого тарифа. Настоящего резервирования, платежей и отправки писем нет. Повтор того же запроса с прежним idempotency key возвращает то же подтверждение. Новое сообщение сбрасывает выбранный отель даже при ошибке модели. Подтверждённую поездку можно восстановить после перезагрузки и скачать текстовым планом.

Повторяющиеся пометки «демо» убраны с карточек, чата и верхних блоков. Короткое пояснение о показе прототипа остаётся перед подтверждением и в скачанном плане. Внутренние поля происхождения цен (`source_kind: demo`, `is_demo: true`) сохранены.

`travel_setting` хранит настроение поездки отдельно от города. Для природы предлагаются Карелия (Сортавала), Алтай (Чемал), Селигер (Осташков). В этом сценарии сравниваются до трёх публичных страниц каталога (60 объектов, без дублей), исключаются городские квартиры, используются опубликованные типы размещения и названия домиков/баз. Лес непосредственно у объекта и степень уединения остаются неподтверждёнными свойствами. «На 5 ночей» не может служить доказательством бюджета «за ночь»: отдельный валидатор требует явного указания периода.

Анимация `travel-window.js/css` заменяет стартовые карточки сразу после отправки запроса. Она получает настоящие события из агента: understanding → understood → searching → comparing → complete. Локальный progress-сервис агента слушает только `127.0.0.1:15052` (`AGENT_PROGRESS_PORT`). Core проксирует его через защищённый владельцем сессии GET `/api/sessions/{id}/progress?key=...`; адрес настраивается `AGENT_PROGRESS_URL`. Токен связан с владельцем, ID сессии и ключом операции; события исчезают через 6 минут. Это отдельный локальный канал, не изменение gRPC-контракта. При развёртывании Core и агента в разных контейнерах нужен соответствующий внутренний адаптер progress-канала; основной поиск и оформление от него не зависят.

Таймер не имитирует этапы: через 25 секунд он только добавляет подсказку о продолжающемся поиске. Шторы открываются после получения разобранных условий; выводятся до трёх условий. При уточнениях прежние результаты остаются видны. После поиска окно за 850 мс раскрывается в фото первой карточки, остальные появляются следом. `prefers-reduced-motion` отключает движение. При сетевой ошибке запрос остаётся доступен для безопасного повтора.
