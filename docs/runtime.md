# Запуск и диагностика

Основной путь — `docker compose up --build` из корня и http://localhost:8080. Конфигурация и ресурсы перечислены в [README](../README.md).

## Подготовка

1. Docker собирает `app`, `agent`, `model`. Пока Core не запущен, порт 8080 может быть недоступен.
2. Модель скачивает 2,50 ГБ весов Qwen3-4B-Instruct-2507 Q4_K_M в volume `models`; поддерживается докачка и проверка SHA-256.
3. llama.cpp загружает модель, агент прогревает контексты разбора запроса и подбора направлений.
4. Core проверяет модель и агента, затем открывает UI. 100% загрузки файла ещё не означает завершения прогрева.

`app` запускается одновременно с моделью, чтобы показывать подготовку. До готовности операции поездки возвращают 503. `/health` проверяет процесс, `/ready` — готовность полного пути. Агент открывает gRPC после прогрева.

## Скачивание без ручной установки

В обычном запуске не нужны `.env`, LLM API-ключ, Hugging Face account, Python, Go или установленный на компьютере llama.cpp. Docker собирает всё сам. Доступ к приватному командному репозиторию GitHub требуется до запуска; жюри получает его через организацию хакатона.

Весовой файл загружается из публичного `unsloth/Qwen3-4B-Instruct-2507-GGUF` на Hugging Face. Revision, размер 2 497 281 120 байт и SHA-256 закреплены в `docs/docker-runtime.json`. Загрузчик проверяет хеш во время скачивания, сохраняет промежуточный файл и при сетевом обрыве автоматически повторяет запрос с докачкой (до пяти попыток за один запуск контейнера). Готовые веса остаются в Docker volume `models`; обычный перезапуск их не скачивает заново. Повреждённые веса не запускаются.

Первой сборке также нужен доступ к Docker Hub, GitHub Releases, Ubuntu package mirrors, PyPI и Go module proxy. Штатная команда не обходит блокировки сети. При отключённом интернете или недоступном источнике срок установки гарантировать нельзя. На линии 20 Мбит/с одни веса потребуют не менее 16 мин 39 с; ориентир до 10 минут предполагает более быструю сеть и достаточную производительность CPU. Скачивание, сборка и прогрев входят в общее время установки.

## Время и ресурсы

Проверенный режим: 4 общих ядра CPU, 5,75 GiB лимитов RAM на три сервиса, без GPU. Модель ограничена 5 GiB, агент — 512 MiB, Core — 256 MiB. Docker нужен запас до 6 GiB, операционной системе — дополнительная память.

Последний холодный прогон кода `2799fe5` из GitHub: **7 мин 17 с до `/ready`, 7 мин 54 с до первого ответа**. Linux ARM64 в Docker Desktop на Mac, около 8 ГБ Docker RAM; новый builder без кеша, пустые тома, без `.env`. Установка Docker не включена. Скачивание 2,50 ГБ, сборка и первый прогрев включены. [Условия, времена и логи](validation/cold-start-2026-10-29/README.md).

Предыдущие [замеры CPU](validation/docker-cpu-2026-10-27/README.md) и [прогон 5 мин 25 с](validation/jury-clean-2026-10-28/README.md) относятся к указанным в них версиям и условиям. Они сохранены как история, не как обещание скорости текущей версии. После перезапуска модели прогрев выполняется снова; обычный перезапуск не скачивает сохранённые веса.

Docker выбирает нативную архитектуру. [Актуальный прогон AMD64 с defaults](validation/amd64-defaults-2026-10-28/README.md) выполнен через эмуляцию на Apple Silicon: сборка, скачивание, автоматический прогрев и HTTP-сценарий прошли. Холодный запуск занял 19 мин 32 с; это не замер физического Intel/AMD и не подтверждение ориентира 10 минут. В Dockerfile предусмотрен старый сборщик без автоматического `TARGETARCH`: архитектура определяется по Ubuntu-образу, включать BuildKit вручную не требуется.

## Диагностика

```sh
docker compose ps
docker compose logs app agent model
docker compose exec agent python -m travel_agent.model_check
```

`model_check` делает настоящий запрос к модели. Первый прогрев автоматически допускает до 900 с на медленном CPU; создавать `.env` ради него не нужно. Это верхний предел ожидания, а не обязательная задержка: UI открывается сразу после готовности.

Для пользовательского запроса Compose по умолчанию даёт до 300 с: это предотвращает преждевременный `turn_timeout` на медленном CPU. Быстрый ответ возвращается сразу, дополнительного ожидания нет. Параметры прогрева и ответа уже заданы в Compose; для штатного запуска править `.env` не требуется. Время скачивания в предел прогрева не входит. Если ошибка повторяется, проверьте RAM, загрузку CPU и логи модели; увеличение ожидания не ускоряет inference.

Для изменения настроек используйте `.env.example` как шаблон. В macOS/Linux: `cp .env.example .env`, в PowerShell: `Copy-Item .env.example .env`. Не перезаписывайте уже заполненный файл. Передача токена жюри описана в [secrets.md](secrets.md).

## Данные

`trips` хранит поездки, `hotel-content` — кэш карточек, `models` — веса, `startup` — файл прогресса. Обычный `docker compose down` сохраняет volumes. Ключ `-v` удаляет сохранённые данные и потребует повторной загрузки весов.

`JOURNEY_DATA_SOURCE=public` требует доступа к внешним источникам. `synthetic` явно выбирает учебный каталог; это другой набор данных. Даже при синтетических данных первая установка скачивает образы и модель.

Для разработки на Apple Silicon сохранён отдельный [нативный launcher](local-setup.md) с Metal и портом 18080. Он использует собственный runtime-манифест и не является командой сдачи.
