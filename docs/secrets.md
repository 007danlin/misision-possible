# Передача секретов организаторам

Основной Docker LLM-провайдер — локальный llama.cpp, модель Qwen3-4B-Instruct-2507 Q4_K_M; ключ LLM не требуется. `.env.example` содержит имена переменных с пустыми значениями: Docker Compose подставляет значения по умолчанию. Необязательный `TRAVELPAYOUTS_TOKEN` берётся из кабинета Travelpayouts Data API. При использовании внешнего LLM создайте отдельный ключ для жюри и укажите провайдера и модель в настройках.

В корне репозитория находится бинарный `secrets.env.age`, зашифрованный публичным ключом организаторов. Размещение именно в корне, вместе с `.env.example`, — прямое требование [инструкции организаторов](https://docs.ostrovok.tech/s/b9e6ec5e-5ad6-4091-9c85-a48eee9b21cc/doc/shifrovanie-sekretov-klyuchej-6Qhc4gJOPZ). Конфигурация инфраструктуры хранится в `infra/`; файл передачи секретов остаётся в корне.

В зашифрованный `.env` включён `TRAVELPAYOUTS_TOKEN` и полный набор поддерживаемых настроек из `.env.example`. Токен нужен для кэша прямых авиаперелётов и передаётся только серверному агенту. Локальной Qwen, публичным карточкам отелей, OSRM, OpenStreetMap, MET Norway и Open-Meteo отдельные ключи не нужны.

Организаторам для запуска с переданным токеном нужно расшифровать файл своим закрытым ключом в корне клона и запустить Compose:

```sh
age --decrypt -i /path/to/organizer-private-key -o .env secrets.env.age
docker compose up --build
```

Compose автоматически читает корневой `.env`. В нём используется адрес модели внутри Docker (`http://model:8082/v1`), поэтому локальные службы на компьютере разработчика не нужны. Открытый `.env` остаётся локальным и исключён из Git. После любого изменения `.env` обновите зашифрованный файл:

```sh
age -r age1932fu7f70rwyfhaxflyfszz4gf6avxwc95wc0yjwm6zns9tspycqpgdnc0 -o secrets.env.age .env
git ls-files .env  # вывод должен быть пустым
git add secrets.env.age .env.example .gitignore
```

Зашифрованный файл должен попасть в коммит и ветку сдачи. Расшифровать его можно только закрытым ключом организаторов; открытые ключи API не отправляйте в чат или документацию.

## Проверка комплекта 28 октября 2026

- В оставшемся коде используются два имени API-ключей: `TRAVELPAYOUTS_TOKEN` и `LLM_API_KEY`. Токен Travelpayouts включён; `LLM_API_KEY` пустой, потому что основной inference локальный.
- Запрос с передаваемым токеном к используемому приложением `api.travelpayouts.com/v1/prices/direct` вернул HTTP 200 и `success=true`. Это подтверждает доступ к Data API, но не наличие билетов на любые даты и не право настоящего бронирования.
- Публичный ключ получателя сверён с актуальной страницей организаторов; `secrets.env.age` заново сформирован из проверенных настроек. Адрес модели — контейнерный `http://model:8082/v1`, имя соответствует Docker-манифесту.
- ETG/Intui и платёжные API в приложении не подключены. Для публичных карточек, маршрутов, карты и погоды ключи не используются. Аккаунты удалённых сервисов не требуются.
- Расшифровка конечного файла требует закрытого ключа организаторов, которого у команды нет. Перед шифрованием проверены состав и значения конфигурации; успешность расшифровки именно их закрытым ключом команда независимо проверить не может.
