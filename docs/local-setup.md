# Автономный запуск на этом Mac

Все файлы находятся внутри `Хакатон "Островок"/misision-possible`.
Обычная Ollama и её модели, настройки других проектов, их Docker-контейнеры и порты не используются.

Дважды нажать **«Запустить О!дин запрос.command»** в папке хакатона.
Откроется [приложение](http://127.0.0.1:18080). Первый запуск загружает Qwen в память,
затем открывает интерфейс. Модель локальная, ключи не нужны. Поиск реальных отелей и их фотографии требуют интернета; учебный расчёт полной поездки работает на локальном каталоге.
Для остановки — **«Остановить О!дин запрос.command»**.

Из терминала в репозитории:

```sh
python3 scripts/local.py start
python3 scripts/local.py status
python3 scripts/local.py stop
```

Состав:

| Что | Путь / адрес |
|---|---|
| Qwen3.5-9B, Q4_K_M | `.runtime/models/qwen3.5-9b/Qwen3.5-9B-Q4_K_M.gguf`, ~5,29 GiB |
| Автономный llama.cpp b11853 | `.runtime/inference/llama-b11853/` |
| Inference API | `127.0.0.1:18082`, доступ только с этого компьютера |
| Go Core + UI | `.runtime/bin/core`, `127.0.0.1:18080` |
| Python gRPC agent | `agent/.venv/`, `127.0.0.1:15051` |
| Поездки и idempotency | `.runtime/data/trips/*.json` |
| Логи | `.runtime/logs/` |
| PID только этих процессов | `.runtime/processes.json` |

Runtime и веса скачаны отдельными файлами, не symlink на модели другой задачи.
SHA-256 модели сверен с Hugging Face LFS; источник, лицензия, размер и хеши записаны
в `docs/local-runtime.json`. Веса и runtime исключены из Git; лицензия рядом с моделью.
Во время работы остаются общими только ресурсы компьютера — память и GPU. Поэтому
одновременный запуск нескольких больших локальных моделей всё ещё может влиять на скорость.

Если перенести исходники на другой Apple Silicon Mac, нужны Python 3.12+ и Go:

```sh
python3 scripts/setup-local.py
python3 scripts/local.py start
```

Bootstrap скачивает проверенные по хешу runtime и модель в `.runtime`, устанавливает Python-зависимости
в `agent/.venv` и собирает Core. Go-кэши bootstrap тоже лежат в `.runtime/cache`.
Никаких глобальных пакетов, автозапуска macOS и общей Ollama он не меняет.

## Правки локального интерфейса

Локальный запуск задаёт `LOCAL_WEB_DIR` на `backend/core/web`: изменения HTML, CSS и JS появляются после обновления страницы без пересборки Core. Если переменная не задана, Core использует файлы, встроенные при сборке.

Проверка на работающем сервере: `node scripts/ui-hotel-card-navigation.cjs`. Она создаёт отдельную поездку и проверяет переходы по всей карточке и отдельную кнопку выбора, даты и гостей, пересчёт, оформление прототипа, PDF и историю.

## Умный подбор отелей и история

Главная `/` использует сохранённую страницу Островка. Плашка с `new` открывает `/plan.html`.
Поиск использует публичные карточки отелей; цены рассчитывает прототип, API актуального наличия не подключён.

- Запрос о лесе предлагает направления с фотографиями. Выбор сохраняет пожелания.
- Точные простые команды (возраст детей, число ночей, «подешевле») проходят тот же подбор без повторного вывода Qwen. Произвольные формулировки разбирает Qwen3.5-9B.
- Число детей проверяется независимо; неизвестные возраста уточняются для каждого ребёнка.
- В оформлении нажмите на заезд, выезд или гостей. Сохранение пересчитает все показанные тарифы на сервере. Выход за бюджет требует отдельного подтверждения новой суммы.
- «История» рядом с «Новый поиск» показывает до 100 сохранённых поисков этого браузера. Открывает переписку, варианты и оформление; переключение не создаёт новый запрос к модели.
- Переписка хранится на сервере (до 100 сообщений на поиск), доступ ограничен cookie владельца. Очистка cookie закрывает доступ к старой истории.

Окно О! показывает настоящие стадии `/progress`, а не таймерные обещания. При повторном поиске старые карточки остаются. Для reduced-motion анимация отключается.

Проверки: `node scripts/ui-history-edit.cjs` — полный путь через настоящий Core/agent, историю и оформление; `node scripts/ui-window-states.cjs` — контролируемые состояния анимации; `agent/.venv/bin/python scripts/bench-hotel-turns.py` — реальный Qwen и пять детей; `scripts/bench-hotel-freeform.py` — дополнительные свободные формулировки. Замеры сохраняются в `.runtime/bench-hotel-*.json`; это замеры на этом Mac, не гарантия времени ответа.

## Прежний сценарий полной поездки (`/plan.html?mode=demo`)

1. Пример «Море на двоих»: Москва → Сочи, 10–15 ноября 2026, двое,
   до 120000 рублей на дорогу, отель, трансферы и сборы, без ночных рейсов.
2. Выбрать A за 109000 рублей.
3. Написать «Теперь максимум 100 тысяч, остальное оставь».
4. Увидеть B за 97000 рублей, разницу −12000 рублей и условия отмены.
5. Принять изменение и отдельно подтвердить **учебное** оформление.
6. Перезагрузить страницу — поездка сохранится.

Учебные данные доступны для Сочи, Казани, Владимира и Ярославля. Отправление из Москвы,
двое взрослых, от 1 до 14 ночей в ноябре–декабре 2026 года, выезд до 31 декабря.
За пределами каталога агент уточняет запрос или сообщает об отсутствии данных.

Рабочий интерфейс **О!План** использует утверждённый дизайн Островка: диалог слева,
три предложения справа и подробности выбранной поездки. [Описание интерфейса](interface.md).

## Проверки

```sh
cd agent
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m evals.run --output evals/results/qwen-project-local.json
cd ../backend/core
go test -race ./...
cd ../..
python3 scripts/trip-smoke.py
```

Для проверки интерфейса установлен Chrome. В этой папке уже есть изолированная
test-зависимость Playwright; на чистом компьютере её можно восстановить без глобальной установки:

```sh
npm install --prefix .runtime/browser --save-exact playwright-core@1.56.1
node scripts/ui-smoke.cjs
```

Скрипт проходит запрос, выбор A, снижение бюджета, принятие B, учебное оформление и
перезагрузку страницы. Скриншоты — `.runtime/screenshots/`. Для другого пути Chrome
задайте `CHROME_PATH`. Не запускайте этот smoke и eval одновременно: они делят одну Qwen.

Последние evals и trip-smoke действительно вызывают локальную Qwen.
Обычные unit-тесты используют подставную модель и проверяют код, не интеллект Qwen.

UI и сессии работают в специальном local demo mode, привязанном к loopback.
Каждому браузеру выдаётся HttpOnly cookie; чужие поездки по одному ID недоступны.
Серверная revision, idempotency и повторная проверка плана выполняются Core.
Хранилище файлов рассчитано на один процесс Core. Для внешнего/многосерверного запуска
его нужно заменить production-хранилищем Луки и использовать Auth.

Проверка обновления 27.10.2026: 87 Python-тестов, Go-тесты и браузерные сценарии главной, живого окна, истории и оформления прошли. На трёх свободных запросах локальная Qwen дала проверенный результат за 22.36, 27.39 и 27.95 с; уточнение пяти возрастов с поиском — 1.36 с. Эти результаты зависят от текущей нагрузки и прогрева модели. В быстром пути меняется только извлечение однозначных команд; фильтрация всего полученного каталога, бюджет и ограничения остаются теми же.

## Ускоренный разбор пожеланий

Локальный запуск включает `HOTEL_COMPACT_WIRE=1`: Qwen3.5-9B остаётся той же моделью,
но в режиме отелей выводит короткие типизированные поля вместо повторения текста пользователя.
Адаптер восстанавливает прежний контракт, прикрепляет точный исходный текст как evidence;
действующие проверки, подбор всего набора кандидатов и расчёт цен остаются на сервере.
Бюджеты передаются в рублях и точно преобразуются в копейки; цена за ночь имеет отдельное поле.
Грамматика запрещает ночную цену без того же буквального подтверждения, которое требует валидатор.
Для сообщений длиннее 500 символов, других провайдеров и исправления ошибок сохраняется полный протокол.
Выключить новый формат для диагностики: запустить агент с `HOTEL_COMPACT_WIRE=0`.

При запуске агента/модели прогреваются инструкции, готовые ответы не подставляются.
Для Qwen с recurrent-контекстом используются checkpoints с шагом 64, microbatch 128,
8 checkpoints на слот и ограничение RAM-кеша 1024 MiB. Это сокращает повторное чтение
неизменных инструкций. N-gram speculation отключена: на коротких структурированных ответах
в измерениях она увеличивала задержку. Изменения относятся только к локальному launcher.

Проверка качества и времени на реальном Qwen с фиксированным каталогом:
`HOTEL_COMPACT_WIRE=1 agent/.venv/bin/python scripts/bench-hotel-latency.py`.
Сквозная проверка браузер → Core → Qwen → публичный каталог → карточки:
`node scripts/ui-latency.cjs`. Отчёты: `.runtime/latency-1.json`, `.runtime/latency-browser.json`.
Фиксированный каталог в первом тесте нужен для воспроизводимой проверки фильтрации;
он не используется рабочим приложением. Первый отчёт отдельно сохраняет HTTP-время
и время inference, чтобы очередь не выдавалась за скорость самой модели.
Параллельные запросы к одному слоту, другие локальные модели и скорость сайта могут
увеличивать полное ожидание; 5–10 секунд не являются гарантированным SLA.

Последний сквозной прогон 27.10.2026 после прогрева: Казань с точными датами,
завтраком, парковкой и бюджетом — 9,883 с до трёх карточек; семейный запрос с
пятью детьми — 4,458 с до уточнения возрастов; ответ возрастами — 2,288 с до
карточек; лес, уединение, собака и бюджет — 4,909 с до выбора направления.
Модель и остальные приложения не заменялись/не останавливались ради замера.
Подробности и хеши кода — в `.runtime/latency-browser.json`. Это один измеренный
прогон, а не гарантия для любой формулировки или нагрузки.

### Повторная проверка скорости — 27.10.2026

Постоянные инструкции отделены от меняющегося контекста на границе сообщения,
где Qwen сохраняет recurrent checkpoint. Имена/позиции отелей остаются в контексте;
повторные описания причин выбора из карточек убраны из извлечения требований.
Ответы на однозначное «Почему ты выбрал второй отель?» и полностью разобранные
составные правки бюджета/удобств идут без нового вызова модели. Неизвестная часть,
условие, альтернатива или противоречие возвращают весь запрос Qwen. Подбор кандидатов,
проверка бюджета и остальные ограничения не изменены. Эксперимент с исключением
заранее разобранных чисел из генерации отклонён: в живом тесте потерял другие условия.

Проверка: `node scripts/ui-speed-regression.cjs`. Полный браузерный прогон с настоящей
Qwen и публичным каталогом: сложная семья — 25.846 с, возраста пяти детей — 0.653 с,
составная правка — 0.259 с, объяснение выбора — 0.066 с, точные даты/завтрак/парковка —
18.384 с, лес/уединение/собака — 5.484 с. Состояние семьи, бюджета и сохранённых пожеланий
проверено утверждениями. Отчёт: `.runtime/latency-final-browser.json`.
В этом прогоне у двух длинных запросов сама генерация заняла 19.989 и 15.218 с
(3.45–4.01 токена/с). Поэтому 5–10 с для всех свободных запросов на текущей нагрузке
не достигнуты; скорость коротких правок не является доказательством общего SLA.
VeloEdit и чужие прогоны не приостанавливались. После этого дополнительно закреплено
сохранение отдельного пожелания «подальше от города» вместе с лесным направлением.
