# Единая поездка: реальные отели, P1 и P2

Обновление 27 октября 2026. Основной интерфейс `/plan.html` теперь использует реальные публичные карточки Островка и отдельную оценочную модель дороги/трансферов. Базовый режим не требует ключей; необязательный ключ Travelpayouts подключает кэш реальных прямых перелётов. Ни подтверждённого наличия на даты, ни реальной покупки эта интеграция не создаёт.

## Что доступно без ключа

Проверены обычная публичная страница каталога и страница выбранного отеля: HTTP 200, данные `__NEXT_DATA__`. Доступны название, адрес, координаты, фото CDN, удобства, категории номеров, часы заезда/выезда, отдельные платежи/политики и первая выборка отзывов Островка. Пример живого прогона: «Спа-отель Грейс Арли», 610 отзывов в источнике, доступны 10 текстов; «Грейс Лазурь» — 208/10; «Грейс Круиз» — 459/10. Счётчики меняются со временем.

Используется только обычный публичный HTML: без входа, закрытых API и обхода ограничений. Получение страницы не является гарантией разрешения на массовое повторное использование. Адаптер ограничен поиском пользователя, 20–60 кандидатами и деталями максимум трёх выбранных объектов; медиа не скачиваются массово, изображения загружаются браузером с CDN. Для долговременного публичного продукта нужны согласованный источник и условия использования.

[ETG Content API](https://docs.emergingtravel.com/docs/content-api/) доступен по отдельному запросу; синхронизация контента должна быть отделена от живого поиска наличия. Здесь Content API не вызывается. Токен Travelpayouts предоставлен пользователем и хранится локально вне Git; это не ключ ETG.

## Реальные сведения и расчётные значения

- Реальные: идентичность отеля, фото именно этого объекта, публичные удобства/политики, координаты, доступные отзывы. У каждого объекта есть ссылка и время проверки.
- Оценочные: цена проживания от справочной цены без дат, питание/возвратный тариф в модели, транспортное расписание и стоимость, автомобильный трансфер. На карточке `≈` и одна раскрываемая строка об источниках.
- Не подтверждены: наличие категории для всех гостей, тариф на даты, питание/отмена/сборы конкретного предложения, детские кресла и обслуживание питомцев. Неизвестные обязательные условия блокируют прохождение подбора; неизвестное не превращается в `pass`.
- Трансфер рассчитан по координатам отеля: расстояние по прямой × 1,5, 35 км/ч + 15 минут, 800 ₽ + 45 ₽/км, машина на 3 человека. Это явные допущения, не дорожная навигация и не оферта такси.

Новые поездки по умолчанию используют `JOURNEY_DATA_SOURCE=public`. Прежний вымышленный каталог доступен только при явном `synthetic`; ошибки публичного источника не подменяются вымышленными отелями. Детали кэшируются на 6 часов; если обновить не удалось, сохранённые сведения отмечаются как устаревшие. В Docker кэш хранится в отдельном volume `hotel-content`. Без отзывов карточка и расчёт продолжают работать, а блок отзывов показывает отсутствие текстов.

## P2

| Возможность | Что работает |
|---|---|
| Ранний заезд | Сохранить/изменить/удалить пожелание после оформления; включить в PDF. Статус **черновик, не отправлено и не подтверждено**: реального канала отеля нет |
| Трансфер к готовому отелю | Рассчитать оба трансфера, показать доплату, принять или отказаться, сохранить итог и экспорт. Повторное добавление блокируется; конфликт времени не проходит |
| Предпочтения между сессиями | Явное сохранение в этом браузере, просмотр, редактирование, удаление и отдельное применение к запросу; без скрытого профилирования |
| Совместный выбор | Ссылка на снимок подборки на 7 дней, голос по одному варианту, повторный голос заменяет предыдущий, отзыв доступа. Имя гостя и переписка не публикуются |
| Напоминание | Скачать ICS с напоминанием за день; начинает работать после импорта пользователем в календарь. Приложение не обещает фоновую доставку уведомлений |
| География | Город отправления задаёт пользователь; справочник 1117 городов для геопозиции и оценки автомобиля. Авиа/железная дорога — проверенные пары небольшого каталога; публичные отели — география адаптера |

Совместная ссылка работает только там, откуда доступен этот сервер. Адрес `localhost` не делает проект общедоступным. Платёж, аккаунты и реальная отправка пожеланий отелю не реализуются этим локальным прототипом.

## История: первоначальная реализация P0 на вымышленном каталоге

Ниже сохранено описание предыдущего этапа; текущий источник и границы указаны выше.


Основной интерфейс — `/plan.html`. Запрос с бюджетом на дорогу, отель и трансферы собирает всю поездку в той же сессии. Отдельный подбор отелей остаётся доступен, если пользователь просит только размещение.

## Что реализовано

- Общая цена проживания, дороги туда-обратно, двух трансферов и сборов. Личный резерв показан отдельно; общий бюджет не стирается при уточнении лимита на отель.
- Расписание четырёх сегментов, выход из аэропорта/вокзала, окно заселения, ранний приезд и запас перед обратным отправлением. Все значения содержат дату, смещение и часовой пояс. Неподтверждённые обязательные требования не проходят проверку.
- Вместимость номеров и машин, детские кресла, пересчёт всех услуг при смене гостей и длительности.
- Серверный пересчёт по каноническим данным перед выбором и подтверждением. Цена из браузера не принимается. Конфликт времени нельзя обойти согласием на превышение бюджета.
- Изменение выбранной поездки через сравнение «было → стало». Можно принять предложение или вернуть прежний план; ошибка/отсутствие нового варианта сохраняет возможность восстановить прежний.
- Компактные разделы «Номер и условия», «Отзывы», «Дорога и трансферы», «Состыковки»; фильтр отзывов по теме и сравнение вариантов по полной цене.
- Оформление и сохранение всей поездки, восстановление после обновления, маршрут и общая стоимость в PDF.
- Одна короткая раскрываемая строка о происхождении расчёта и согласие перед подтверждением. Повторяющихся плашек «демо» на каждом компоненте нет.

## Данные и границы

Полный сценарий использует `agent/travel_agent/journey_catalogue.json`: 12 **вымышленных** объектов с отдельными текстами отзывов и учебными тарифами/расписаниями. Направления из Москвы: Сочи, Казань, Ярославль, Сортавала; даты 1 ноября — 31 декабря 2026. Фотографии иллюстрируют сценарий. Это не реальные предложения Островка и не реальные отзывы гостей существующих отелей.

Обычный hotel-only поиск продолжает использовать публичные карточки Островка. При отсутствии текстов отзывов показывает честное пустое состояние; вымышленные отзывы из нового каталога к реальным объектам не подмешиваются. Внешний API контента/тарифов не подключён. Расширение источника — отдельная задача с доступом и разрешёнными данными.

География полной поездки ограничена данными, а не обещанием произвольного маршрута: для неподключённого направления пользователь получает объяснение, его условия не заменяются. Питомцы в сценарном каталоге не подтверждены. Погода и полноценная карта в эту реализацию не входят.

## Архитектура

`journey.py` — единый детерминированный расчётчик; модель извлекает только пользовательские условия. Поиск и gRPC `Evaluate` вызывают тот же расчёт. При повторной проверке запись заново читается по ID из каталога, стоимость из сохранённого предложения не является каноническим тарифом.

Core управляет сессией, ревизией, preview и заказом. Новые действия: `accept_journey_change`, `discard_journey_change`, `restore_journey`; существующий `update_hotel_stay` создаёт preview для полной поездки. Действия используют `expected_revision` и `idempotency_key`. Подтверждение хранит неизменяемый снимок `hotel_booking.hotel.journey` вместе с отелем и гостями.

`journey-ui.js` и `journey.css` добавляют блоки к текущей странице, не создавая отдельное приложение. `trip-pdf.js` экспортирует тот же снимок. Progress в Docker настроен через внутренний адрес агента; его порт не публикуется на хост.

## Проверки

```sh
cd agent
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python export_schemas.py
cd ../backend/core
go test -race ./...
go vet ./...
cd ../..
node scripts/ui-journey.cjs
```

Проверки Python включают общий и отельный бюджеты, резерв, стоимость трансферов, конфликт заселения, переход суток, ночные рейсы, детей, сохранение обязательных условий и канонический пересчёт. Go проверяет preview, блокировку оформления до принятия, конфликт независимо от согласия на превышение бюджета, сохранение и идемпотентность.

Браузерный сценарий проверяет свободный запрос, подробности отеля, фильтр отзывов, пересчёт, откат, принятие, оформление, reload, PDF и мобильный экран. Результаты и снимки — `.runtime/screenshots/journey/`; это локальные проверочные артефакты, не опубликованный скринкаст.
