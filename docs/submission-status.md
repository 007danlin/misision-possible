# Статус технической готовности — 29 октября 2026

Текущую конфигурацию определяют корневой [README](../README.md), [Compose](../docker-compose.yml) и [docker-runtime.json](docker-runtime.json). Основная модель — **Qwen3-4B-Instruct-2507 Q4_K_M**, llama.cpp b11853, CPU, без LLM API-ключа. Старые замеры Qwen9B и промежуточные неуспешные прогоны сохранены в отдельных датированных отчётах; они не описывают текущие настройки запуска.

## Что можно воспроизвести

```sh
docker compose up --build
# После старта — необязательная полная проверка из второго терминала:
docker compose exec -T agent python -m travel_agent.verify_running
```

Нужны доступ к командному GitHub, Docker/Compose, интернет и ресурсы из README. `.env`, расшифровка секретов и дополнительные языковые runtime для основного сценария не нужны. Первая команда сама собирает три сервиса, скачивает 2,50 ГБ весов, проверяет SHA-256 и прогревает модель. Вторая команда проверяет реальный HTTP-путь и создаёт одну учебную поездку.

## Соответствие техническим требованиям

| Требование | Реализация и проверка |
|---|---|
| Один репозиторий в организации хакатона | `ostrovok-hackathon-2026/misision-possible`, основная ветка `main` |
| README, Compose, Dockerfile, `.env.example` | Файлы в репозитории; Dockerfile для каждого из трёх сервисов |
| Запуск одной командой, UI на 8080 | `docker compose up --build`, `http://localhost:8080` |
| Все runtime-зависимости в контейнерах | Go Core/UI, Python agent, llama.cpp; веса загружаются автоматически |
| Непривилегированный пользователь и multi-stage build | Каждый сервис собирается отдельно и работает с UID 10001 |
| Healthcheck и готовность | `/health` — процесс, `/ready` — модель и агент; healthchecks в Compose |
| Большие модели вне Git, OpenAI-совместимое API | GGUF в volume, revision/размер/SHA-256 закреплены; внутренний `/v1` API llama.cpp |
| Linux AMD64 | Docker на x86 выбирает AMD64 нативно; отдельный прогон через эмуляцию — [отчёт](validation/amd64-defaults-2026-10-28/README.md) |
| Секреты без открытых токенов в Git | `.env.example` без значений, `secrets.env.age` в корне, [инструкция](secrets.md) |
| Скринкаст | Публичная ссылка находится в README |
| Ориентир холодного запуска до 10 минут | Последний замер на Mac ARM64: 7 мин 17 с до готовности, 7 мин 54 с до ответа; не гарантия для другого CPU/сети |

На сервере проверяющий может использовать HTTP или контейнерную проверку без браузера. `/api/local/status` сообщает настроенный источник карточек, расчётные цены и учебное бронирование. Публичный контент не означает подтверждённую доступность или продажный тариф.

## Проверки кода и запуска

- **313 Python unittest и Ruff** прошли на runtime-коде `2799fe5`. [Подбор направлений: 9/9 сценариев через HTTP и реальную модель](validation/direction-diversity-2026-10-28/README.md); общие пожелания дают 2–3 варианта, узкие ограничения сохраняются.
- Проверка Python-зависимостей, 11 тестов загрузки/докачки/целостности и 3 теста ожидания модели ранее прошли на версии, указанной в [отчёте AMD64](validation/amd64-defaults-2026-10-28/README.md).
- Go Core: форматирование, `go vet`, `go test -race` и сборка ранее прошли; изменения подбора в `2799fe5` не меняли Go Core.
- [Последний холодный ARM64-прогон кода `2799fe5`](validation/cold-start-2026-10-29/README.md): из GitHub, пустой builder и тома, без `.env`; готовность — 437,418 с, первый ответ — 473,981 с. Это проверка запуска и подбора направлений, без полного бронирования.
- Предыдущий [холодный ARM64-прогон](validation/jury-clean-2026-10-28/README.md): новый builder, пустые volumes, без `.env` и ключей; `/ready` — 311,536 с, все healthy — 324,832 с. После старта пройден браузерный путь до публичных отелей, учебного оформления и PDF. Это один замер на M4 с быстрой сетью.
- [Актуальная проверка AMD64 с defaults](validation/amd64-defaults-2026-10-28/README.md) отделяет сборку, прогрев, HTTP-сценарий и ограничения эмуляции. Она не заменяет замер производительности физического Intel/AMD.
- Прежний [языковой прогон 95/95](validation/docker-cpu-2026-10-27/README.md) относится к указанному там окружению и авторскому набору; это не гарантия на неизвестных запросах жюри.

Нативный workflow `Linux AMD64 runtime` подготовлен для `ubuntu-24.04` x86-64: новый builder, пустые volumes, реальные модель и публичные источники, JSON-результат, отдельный критерий 600 с. GitHub Actions организации недоступен: зафиксирована ошибка оплаты/spending limit, новые jobs не назначаются. Этот блокер не является успешной CI-проверкой.

## Ограничения и оставшиеся внешние действия

- Бронирование и платежи учебные; цены расчётные. Настоящие доступность, продажа и заказ у поставщика не подключены.
- Поездки хранятся локально в volume; промышленная авторизация и многопроцессное хранилище не реализованы.
- Результаты пользовательского исследования и влияние на бизнес-метрики не измерены. Подготовленный протокол не выдаётся за проведённое исследование.
- На физическом Linux AMD64 и Windows полный актуальный прогон пока не выполнен. Доступ к источникам, память Docker и скорость CPU/сети остаются условиями запуска.
- Версия сдачи закреплена тегом `submission`; в быстром старте указан checkout этого тега. Runtime-код проверен на `2799fe5`, итоговый коммит обновляет только документацию и доказательства проверок.
- `secrets.env.age`, `.env.example` и инструкция расшифровки находятся в теге. Публичный ключ сверён со страницей организаторов; закрытого ключа у команды нет, поэтому расшифровку конечного файла выполняют организаторы. Страница скринкаста доступна без входа.
